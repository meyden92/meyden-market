# Music video

Work from the Remotion project root as the lead, in the main conversation. `<slug>` is the folder under `videos/` (from `new`, or derived from the song title); the song and lyrics live there. Load `motion-rules`, `remotion-core`, `asset-contract` and `audio` first. Kit and template reference: `references/kit.md`. The kit is a parts bin for timing, lyrics, 3D, plates and finishes; the video's look, typeface and refrain come from its treatment (step 5), so no two videos look alike. Each step ends with its done-when; do not start the next step before it holds.

## Rules

- Lyrics come only from the user's files. Never write, complete or reproduce commercial lyrics.
- One shot per lyric line (or two short lines). Cut on the nearest downbeat. A shot holds at most 3.5-4 s. A set held for a whole verse is a defect. Each shot differs visibly from its neighbours (subject, framing, UI). Stillness is allowed only where the music drops.
- Motion intensity follows section energy. A look or energy the user chose overrides the earlier plan everywhere in the storyboard.
- One lyric typeface for the whole video (`F.lyric`, the treatment's family). Vary weight, size, colour, animation, layout. Diegetic UI (HUD, counters, hashtags, tickers, status bars) may keep its own fonts.
- No caption boxes. Free text with a soft dark shadow, plus a subtle bottom gradient on bright shots. A container only where it is diegetic (a story sticker, a typed post field, a comment field).
- Unlit and past lyric words stay at 40-55 % brightness or more and must read on that shot's background.
- One visual system for the whole video: the chosen treatment (the storyboard's Direction block), its finish (`LOOK` in `theme.ts`: `plain`, a project look or a kit look) and the custom pieces the storyboard lists; colours, glow and texture outside them are a defect. The refrain is staged as the treatment's device says; extruded 3D type is one option, and when it is used it takes `useRefrainMaterials()` and never a mirrored ghost copy.
- No flat full-frame accent-colour backgrounds (acid green reads as a green screen). Keep a base light level; no near-black frame between hits.
- No placeholder-looking empties (black feed tiles), no repeated words (a sticker repeating the caption), no text cut by the frame, bottom of any text at least 90 px above the frame edge.
- At most 3 full-frame white flashes per second.
- Plates, planes and sets cover the camera's view over the whole camera move, with about 10 % to spare; no plate edge, black band or void reaches the frame at any point of a move.
- Lyric and refrain text sits on a calm area: no particles, stars, snow or busy texture behind the letters.
- A material that must read as something real (water, fire, glass) is built from a reference plate or still the storyboard names; a procedural stand-in needs a still the lead has accepted.
- Word times from alignment are good to about 0.2 s.

## Steps

1. **Inputs.** Look for the song and the lyrics before asking: files the user named, then the project root and `videos/<slug>/` (audio files; `lyrics.txt`, `song.txt`, `*lyric*`). Show what you found and ask which to use. Copy the song to `public/audio/<slug>.<ext>` and the lyrics to `videos/<slug>/lyrics.txt`, dropping any preamble above the first sung line or header (a title, `=== LYRICS ===`). Ask for a missing file only after that search. Done when both files exist.
2. **Analyse.** `node "${CLAUDE_PLUGIN_ROOT}/scripts/analyze-music.mjs" public/audio/<song> videos/<slug>/research/song.json --fps 30`. Done when bpm, downbeats and sections are present.
3. **Align (paid).** Blocks come only from section headers: a `[SECTION]` line on its own starts a section, every other non-empty line is one sung line, and every sung line needs a header above it. Users' lyrics arrive in other shapes (no headers, blank-line stanzas, `Chorus:`, `(Chorus)`, `[Verse 1: Artist]`). If `lyrics.txt` is not in this format, propose headers from the stanzas, repeated lines and the `song.json` sections, show the sectioned outline (header, first words, line count) and write only after the user approves. Add, rename or remove header lines only; never change, add or reorder a sung line. Strip artist credits (`[Verse 1: Artist]` → `[VERSE 1]`). Header edits after alignment are free: re-running `node "${CLAUDE_PLUGIN_ROOT}/scripts/audio.mjs" plan <slug> align --audio public/audio/<song>` refreshes the sections without a paid call. When it prints a call instead, state the cost (`get_pricing` for `fal-ai/elevenlabs/forced-alignment`) and ask. Only after a yes, align as the `audio` skill's Lyric alignment section says (upload, call, `save`). Done when every sung line has a header and `research/alignment.json` exists with no line without words, or the gaps are reported.
4. **Blocks and scaffold.** `node "${CLAUDE_PLUGIN_ROOT}/scripts/music-blocks.mjs" videos/<slug>/research/song.json videos/<slug>/research/alignment.json videos/<slug>/blocks.json --fps 30 --stubs src/videos/<slug>` merges analysis and alignment into `blocks.json` (edges snapped to downbeats, a `tail` block after the last vocal, pickups flagged) and writes a `Pending` stub per block plus `worlds.ts`. A boundary with confidence below 0.5 is printed as LOW CONFIDENCE: check it by ear. Check against the lyric structure: verse, pre-chorus, chorus, bridge, tail. Then copy `${CLAUDE_PLUGIN_ROOT}/templates/music/` into the project without overwriting existing files (`cp -Rn`), renaming every `__SLUG__` path segment to the slug, and replace in file contents `__SLUG__`, `__W__` 1920, `__H__` 1080, `__FPS__`, `__DURATION__`, `__TOTAL__`, `__BAR__` from `blocks.json` (`fps`, `duration`, `total`, `bar`) and `__BPM__` from `song.json` (`bpm`). Overwrite `remotion.config.ts` with the template's (adds `--gl=angle` as the default renderer). `src/lib/music/` comes from setup. Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/gen-index.mjs" <slug>` to register the compositions (one music video is registered at a time; see `references/kit.md`). Done when every lyric line belongs to a block, every block edge is a downbeat and `npx tsc --noEmit` is clean.
5. **Interview and direction.** Load the `direction` skill and follow it, with its Lyric music video section: inventory, three treatments that differ in world, device, form and type, a style frame per treatment, the check against the Default and the fingerprints. Then run the `video-interview` method for the open choices only: the treatment, per-section energy (including the bridge and the drop), and palette or typeface only where the user changes the treatment's. References show craft, not a style to copy. Send the stills with absolute paths, then ask with a recommendation. Done when the choice is logged with its still in `research/interview.md` and `research/direction.json` exists.
6. **Custom pieces.** From the chosen treatment, list what the kit does not have and this video needs: the lyric font, a project look when plates are printed in a treatment of their own, shaders, particles, transitions, lyric treatments, shared 3D props. Write the shared ones now in `src/videos/<slug>/` (`looks/`, `fx/`, `fonts.ts`), never in `src/lib/` (setup overwrites it).
   - Lyric font: in `fonts.ts`, `loadFont()` from `@remotion/google-fonts/<Family>` with the weights the family has, passed as `lyricFont` in `theme.ts`, with `lyricWeights` set to those weights (regular, medium, bold; one weight three times for a one-weight family). A local file goes through `@remotion/fonts`.
   - Extruded type only: `node "${CLAUDE_PLUGIN_ROOT}/scripts/font-ttf.mjs" "<Family>" <weight> public/fonts/<Family>-<weight>.ttf` and `font3d: staticFile("fonts/<Family>-<weight>.ttf")`, same family as the lyric font or a display family the treatment names.
   Render a still of each piece on a stub block or the treatment's style frame, send it and log the choice. Pieces used by one block only are left to its builder. Done when every shared piece renders a still and `tsc` is clean.
7. **Storyboard.** Fill in `videos/<slug>/STORYBOARD.md` from the scaffolded `videos/<slug>/STORYBOARD.md`: Global section (including effects, minTextPx and materials), block table, and per block a shot list with one row per line (time, line start, what we see, camera, music mapping, lyric treatment, out). Record the treatment, its finish and every custom piece from step 6 under Global. Name the camera move of every shot with its extremes, so plate sizes can be planned against them. Apply the rules above and every user choice. Show it and wait for approval. Done when the user has approved and no shot breaks a rule.
8. **Assets.** Write `videos/<slug>/assets.json`: `{"width": 1920, "height": 1080, "assets": [{"file", "owner", "layer", "prompt", "scale", "status": "pending"}]}`, one entry per image the storyboard needs. `scale` is the largest magnification the storyboard's camera extremes apply to the image (`asset-contract`, Scale; 1 for a still plate). `owner` is the block id that uses it, or `shared` for an image several blocks use; the file is `public/img/<owner>-<name>.png` (`verse1-wanderer.png`, `shared-sky.png`). The names are fixed here, before any prompt is written, and every brief and builder uses them. A music video has no scenes.json. Prompts describe the treatment's world in its own medium. With a kit or project look as the finish, they follow that look's art note instead: plain art, never the look's own treatment (no halftone, pixel, linocut or watercolour words), or it prints twice. Generate per the `assets` skill's `generate` step (fal MCP, cost confirmation, verification), here in the main conversation. Then `node "${CLAUDE_PLUGIN_ROOT}/scripts/validate-assets.mjs" <slug>`. Done when it exits 0, every image was viewed, and no builder wave has started before that.
9. **Theme.** In `src/videos/<slug>/theme.ts` set `LOOK` (the treatment's finish; `PROJECT_LOOKS` for a project look), the palette `C` (from the treatment), `IMAGES` (names of `public/img/<name>.png`), `LYRIC_STYLES` `lyricFont`, `lyricWeights` and `font3d` from step 6, and the optional `defineMusic` fields (`refrainWords`, `highlightWords`, `chips`) from the storyboard. The stubs from step 4 are already wired through `worlds.ts`; do not hand-write stubs. Done when `npx tsc --noEmit` is clean and every `<slug>-<blockId>` composition renders a still.
10. **Build in waves.** Start Studio first (see Studio below) and give the user its URL. Spawn `video-engineer:block-builder` agents, one per block, in waves of at most 3-4 (session limits are tight). Set model sonnet and effort medium explicitly. The first wave holds the flagship chorus (the first chorus, which sets the refrain grammar) and blocks that do not depend on it; blocks that derive from it (later choruses, the final chorus) go in a later wave. Each prompt carries: the storyboard section for the block, the files it may write, the files it must not touch (everything else, the whole kit and the shared custom pieces), the custom pieces it may use, assets with verified sizes, the render commands, the progress-still naming rule and the progress folder. The kit and the shared custom pieces are read-only for builders. Builders write block-only effects, shaders and components in their block folder; a change to a shared piece is reported and the lead makes it between waves. Keep the review state on disk, not in this conversation: one line per block in `videos/<slug>/progress/review.md` (round, accepted shots, open defects). Done when every builder reported and `tsc` is clean.
11. **Progress and feedback.** After each tuning round builders copy 720 px stills to `videos/<slug>/progress/`. Review a round as one contact sheet: copy the round's new stills into `/tmp/<slug>-r<round>/` and run `node "${CLAUDE_PLUGIN_ROOT}/scripts/contact-sheet.mjs" /tmp/<slug>-r<round> /tmp/<slug>-r<round>.png /tmp/<slug>-r<round>.txt 4 480`, and open a single still only to check a defect the sheet shows. Send defects back to the owning builder, and send the good stills to the user with absolute paths as they land. Re-arm the folder watcher after each notification. Typical defects: text cut by the frame, text collisions, duplicated words, low-contrast captions, busy particles behind text, a plate edge or black band at a frame edge, z-fighting, a black frame, a flat accent background, letters through the floor, colour or glow outside the visual system, a look texture that makes a face or lyric unreadable, a material that does not read as what it is. Collect user feedback per block and route it to that block's builder. Done when the user accepts each block.
12. **WIP preview.** On request ("can I see it so far") render the per-block compositions `<slug>-<blockId>` or `<slug>-upto` (set the `upTo` prop to the last block id wanted) at half size (`--scale=0.5`; a scale that does not give whole pixels fails) and send the file path. Pending blocks show the stub. To show a finished block in another look, render `<slug>-<blockId>` with `--props '{"id":"<blockId>","look":"<look>"}'`.
13. **Type unification.** Run `grep -rn "fontFamily" src/videos/<slug>/blocks` and check that every lyric uses `F.lyric` and that no block loads its own lyric font (diegetic UI may keep its own); fix with the owning builder. Done when the grep shows no lyric outside `F.lyric` and a still from each block shows the same lyric face.
14. **QA.** Loop at most 3 rounds:
    1. `sh "${CLAUDE_PLUGIN_ROOT}/scripts/frames.sh" <slug>`: renders the 50 % draft, extracts a frame every 2 s plus each block's first, middle and last frame, and measures flashes, near-black runs and dark frame edges on every frame into `out/qa/flags.txt`. Then `node "${CLAUDE_PLUGIN_ROOT}/scripts/fingerprint.mjs" list --data "${CLAUDE_PLUGIN_DATA}" > videos/<slug>/out/qa/fingerprints.txt`.
    2. Dispatch the `video-engineer:critic` agent with only the absolute paths of `out/qa/contact.png`, `contact.txt`, `flags.txt`, `fingerprints.txt`, every file in `out/qa/frames/`, `STORYBOARD.md` and `blocks.json`, and the instruction to return the JSON object. Never your own opinion of the video, code or the previous round's result. Parse and re-dispatch on invalid JSON as in the `qa` skill.
    3. Pass: no hard failure, every axis at 8 or above, average at 8.5 or above. Write the JSON to `videos/<slug>/out/qa/critic-r<round>.json`; on a pass `touch videos/<slug>/out/qa-passed` and stop.
    4. On fail, route each issue to the owning block's builder (dispatch it again with the critic's lines for its block and its files), wait for the reports, and start the next round.
    After the third failing round, put the remaining failures to the user (fix further, or render as it is and log the accepted failure in `research/decisions.md`). Done when the critic passed or the user decided.
15. **Final.** Render `<slug>` at 1080p with `--gl=angle` to `out/<slug>.mp4`; no other size. Re-render a frame that comes out all black before suspecting code. Record it: `node "${CLAUDE_PLUGIN_ROOT}/scripts/fingerprint.mjs" add <slug> --data "${CLAUDE_PLUGIN_DATA}"`. Then stop Studio. Done when the render exists, the fingerprint is recorded, QA passed or the user accepted its failures, and Studio is stopped.

## Studio

While blocks are built and tuned, Remotion Studio runs in the background from this conversation so the user can preview in real time: `npx remotion studio --port <port> --no-open`, port 3000 or the next free port from 3001 when 3000 is taken. Write the port and PID to `videos/<slug>/out/studio.txt`, reuse a running one, and tell the user the URL once. After the final render, `kill <PID>` and delete `studio.txt`. Renders and stills keep an unpinned port.

## Commands

Use commands that work on macOS and Linux: no `timeout` (macOS has none; use the Bash tool's timeout), no GNU-only flags, quote globs for zsh.

Pickups: a line whose vocal starts before its block shows over the outgoing block. The lyric layer renders the block plus the next block's early lines. A block with `lyricStyles[block]` = `scene` renders its own lyrics.
